# Source and asset provenance

The workload is adapted from [MuJoCo Warp's ALOHA benchmark](https://github.com/google-deepmind/mujoco_warp/tree/79c37d3e8630aba40c2b8023fa9a073fb27b62d0/benchmarks/aloha): `scene_pot.xml` and `lift_pot.npz`. Robot assets come from [MuJoCo Menagerie's ALOHA folder](https://github.com/google-deepmind/mujoco_menagerie/tree/affef0836947b64cc06c4ab1cbf0152835693374/aloha). `assets-manifest.json` maps each selected file to its immutable commit, original path, byte count and SHA256. Only the 135 required runtime files and four attribution files are fetched, approximately 14.82 MB total.

MuJoCo Warp's [repository license](https://github.com/google-deepmind/mujoco_warp/blob/79c37d3e8630aba40c2b8023fa9a073fb27b62d0/LICENSE) is Apache 2.0. The ALOHA robot assets have a separate [BSD-3-Clause license](https://github.com/google-deepmind/mujoco_menagerie/blob/affef0836947b64cc06c4ab1cbf0152835693374/aloha/LICENSE), copyright Trossen Robotics. The downloader preserves these as distinct files, plus both upstream READMEs.

The upstream benchmark README attributes the pot and lid to [PartNet](https://partnet.cs.stanford.edu/). The exact pot/lid asset terms have not been independently established. The robot license and repository license must not be presented as a blanket license for all meshes. Downloading the assets instead of bundling them preserves provenance but does not resolve their underlying terms. Confirm the specific pot/lid provenance before asset redistribution.

The local replay runner adds a native CPU baseline, explicit matching solver settings, batched history collection, validation, timing and output receipts. It is not the upstream official performance harness. Its unchanged source SHA256 is `3ebe1a83688e0289db5bda1feb61af2c82056861e4f9408b38c36cedd3ebcfb0` (frozen-v3). The reference's final-height checks adapt the intention of the [upstream ALOHA lift test](https://github.com/google-deepmind/mujoco_warp/blob/087ac6f0ba9f33edb6bc284eb42aa6c3b16ef1f7/mujoco_warp/_src/unroll_test.py), using explicitly verified distinct pot/lid IDs in the benchmark scene. They are coarse checks and do not reproduce the entire upstream test fixture or establish contact-based grasp success.

No external benchmark numbers are included in this preparation. The collector and figures use only accepted local measurements with matching counts, stacks, model identity and settings.
